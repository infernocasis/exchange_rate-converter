# Страница «Источники данных»

- **Дата:** 2026-10-10
- **Запрос:** новая страница с источниками данных для расчёта; дополнительно — показать, на каких источниках есть потенциальные проблемы.

## Что сделано

Страница `/sources` и эндпоинт `GET /api/sources`. Для каждого источника (транзакции, наличные, курсы) показаны адрес, роль в расчёте, время ответа, сколько записей пришло и сколько годится для расчёта, сами записи в сыром виде и найденные проблемы. Проблемные фрагменты подсвечены прямо в ответе волнистым подчёркиванием с номером-сноской на объяснение. Сверху — схема «3 источника → расчёт» со статусом каждого. В layout добавлена навигация между страницами.

## Финансовая проверка

Формула расчёта выручки не менялась. Диагностика проверена на намеренно сломанной фикстуре навыка `finance-api-audit` и на живом снимке:

| Вход | Ожидалось | Получено |
|---|---|---|
| фикстура, транзакции (19 записей) | годятся 7: paid с валидной суммой и существующей валютой с курсом | 7 ✅ |
| фикстура, `BTC` / `XYZ` / `KZT` | `CURRENCY_NOT_ISO` ×2, `CURRENCY_NO_RATE` ×1, в «годятся» не входят | ✅ (в первой версии входили — исправлено) |
| фикстура, наличные (12 строк) | годятся 4; `MONEY_FORMAT` ×6 | 4, ×6 ✅ |
| живые данные, `/finance2` | `CURRENCY_CASE` в 9 из 9 записей | ✅, совпадает с отчётом аудита |

## Решения и риски

- Внешний вид наследует приложение (slate/indigo, `BaseCard`), чтобы страница не выглядела чужой; выразительный элемент один — размеченный сырой ответ.
- Время ответа курсов не показывается: они почти всегда из 10-минутного кеша, и цифра вводила бы в заблуждение.
- Логика проверок частично дублирует скрипт навыка `finance-api-audit` (он автономный `.mjs` без сборки). При добавлении проверки — обновлять оба места.
- Открытие страницы делает реальные запросы к источникам; курсы берутся из кеша, лимит CurrencyFreaks не расходуется сверх обычного.

# Аудит финансового API

Цель — отчёт, который можно **сразу отдать backend-разработчикам / авторам API**: что не так, где именно, пример значения, чем это грозит клиенту и как исправить.

## Файлы навыка

| Файл | Назначение |
|---|---|
| `scripts/audit.mjs` | забирает ответы 3 эндпоинтов (один раз), прогоняет проверки, пишет `snapshot.json`, `findings.json`, `report.md` |
| `scripts/render-pdf.mjs` | `report.md` → `report.html` + `report.pdf` через установленный Chrome/Edge |
| `fixtures/broken-snapshot.json` | намеренно сломанные данные — для проверки самого навыка |

Каталог проверок с важностью, влиянием и рекомендацией — объект `CHECKS` в `scripts/audit.mjs`. Важность:

- 🔴 **Критично** — клиент падает или выручка **молча искажается** (оплата не учтена, сумма пересчитана не по той валюте).
- 🟡 **Предупреждение** — нарушение контракта, которое клиент сейчас обходит сам (нормализует регистр, обрезает пробелы). Сломает любого другого потребителя API.
- 🔵 **К сведению** — улучшения контракта (нет `id`, нет даты, разный формат источников).

## Шаги

1. **Запустить аудит** из корня проекта (нужен `.env` с ключами):

   ```bash
   node .claude/skills/finance-api-audit/scripts/audit.mjs
   ```

   Скрипт делает **ровно один** запрос к каждому эндпоинту — не запускать в цикле: у CurrencyFreaks маленький лимит. Сервер на Render может просыпаться до минуты — это нормально, ждать.
   Повторно разобрать уже снятые данные без запросов: `--snapshot <dir>/snapshot.json --out <dir>`.

2. **Перепроверить находки вручную.** Открыть `findings.json` и `snapshot.json`; для каждой 🔴 и 🟡 убедиться по сырым данным, что это не ложное срабатывание. Если ложное — убрать из `report.md` и сказать пользователю, какую проверку стоит поправить.

3. **Переписать «Резюме»** в `report.md` (между `<!-- SUMMARY:START -->` и `<!-- SUMMARY:END -->`) человеческим языком для backend-команды:
   - 3–6 предложений, сначала самое важное;
   - конкретика: «все 9 строк `/finance2` отдают валюту в нижнем регистре (`"300 usd"`)», а не «найдены проблемы с регистром»;
   - отделить «ломает сейчас» от «клиент обходит, но это нарушение контракта»;
   - без упрёков и без деталей устройства клиента сверх того, что нужно для понимания влияния.

4. **Собрать PDF:**

   ```bash
   node .claude/skills/finance-api-audit/scripts/render-pdf.mjs docs/reports/api-audit/<папка>/report.md
   ```

   Если браузер не найден — задать `CHROME_PATH`. Если PDF собрать не удалось — отдать Markdown и честно сказать об этом.

5. **Ответить пользователю:** пути к `report.md` и `report.pdf`, счётчики по важности, 2–3 главные проблемы одной строкой каждая. Ничего не коммитить без просьбы.

## Правила

- **Секреты:** ключи API не попадают ни в отчёт, ни в `snapshot.json`, ни в ответ. В примерах `curl` — только `$FINANCE_API_KEY`.
- **Аудитория отчёта** — backend-разработчики и авторы API: каждая проблема = где, пример, влияние, как исправить. Язык — русский, коды проверок и поля — как в API.
- То, что клиент «и так справляется» (нормализует регистр), **не повод убирать проблему** из отчёта — понизить важность до 🟡, но оставить.
- Проблемы провайдера курсов (CurrencyFreaks) — отдельным разделом «к сведению»: это не зона backend-команды.
- Не править код приложения в рамках этого навыка. Если находка говорит о баге в клиенте — упомянуть пользователю отдельно.
- Новая проверка = запись в `CHECKS` + вызов в соответствующей `check*`-функции + случай в `fixtures/broken-snapshot.json`; прогнать навык на фикстуре и убедиться, что проверка сработала.

## Самопроверка навыка

```bash
node .claude/skills/finance-api-audit/scripts/audit.mjs --snapshot .claude/skills/finance-api-audit/fixtures/broken-snapshot.json --out <scratchpad>/fixture-run
```

Ожидается срабатывание всех проверок, кроме `F1-AMOUNT-INVALID`, `F1-EMPTY`, `*-SHAPE`, `HTTP-STATUS`, `HTTP-JSON`, `R-DATE` и проверок валют, которых нет в данных конкретного эндпоинта.
